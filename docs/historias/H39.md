# H39 — Reporte de desempeño de entrenadores

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H39.

Frontend

1. Para el rango elegido, el reporte muestra por entrenador las sesiones impartidas, la calificación promedio y el número de calificaciones recibidas. Un entrenador sin calificaciones muestra «Sin calificaciones».
2. El administrador ordena por calificación promedio o por cantidad de sesiones, ascendente o descendente. Por defecto: promedio descendente; con empate, más sesiones y después nombre alfabético.
   Backend
3. Sesiones impartidas = sesiones en estado COMPLETADA con fecha dentro del rango.
4. Promedio, redondeado a 1 decimal, la misma consulta que H30.
5. El sistema no incluye calificaciones de sesiones que el miembro no tomó.
6. El sistema no permite un rango mayor a 12 meses ni uno con fecha final anterior a la inicial.
7. MIEMBRO Y ENTRENADOR reciben un 403

## Diseño backend e implementación

- **Módulo(s):** `reports, reviews`.
- **Endpoint(s)/componente(s):** `GET /api/v1/reports/trainer-performance`.
- **Modelos Prisma implicados:** `ClassSession, Review, User`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h39.seed.ts`; utiliza fixtures compartidos del grupo `core + classes + slots + routines + machines` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/reports/reports-math.spec.ts; src/reviews/services/reviews.service.spec.ts`.

## Archivos fuente de referencia

- `src/reports/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
