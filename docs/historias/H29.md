# H29 — Calificación de clases y sesiones de entrenamiento

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H29.

Frontend

1. El miembro ve únicamente sesiones COMPLETADA con asistencia ASISTIO; el botón Calificar abre formulario de 1 a 5 estrellas y comentario opcional de 0 a 500 caracteres.
2. Una vez enviada la calificación se muestra “Calificación registrada”; no se ofrece editar ni volver a calificar esa sesión (regla propuesta).
   Backend
3. El servidor rechaza calificar sesiones sin asistencia ASISTIO, no completadas, ajenas o valores fuera de 1..5.
4. No permite dos calificaciones del mismo miembro para la misma sesión; la unicidad se garantiza en la base de datos.
5.

## Diseño backend e implementación

- **Módulo(s):** `reviews`.
- **Endpoint(s)/componente(s):** `GET /api/v1/reviews/eligible-sessions; POST /api/v1/reviews`.
- **Modelos Prisma implicados:** `Review, ClassReservation, ClassSession`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h29.seed.ts`; utiliza fixtures compartidos del grupo `core + classes` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/reviews/services/reviews.service.spec.ts`.

## Archivos fuente de referencia

- `src/reviews/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
