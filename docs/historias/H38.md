# H38 — Tasa de renovación y cancelación de membresías

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H38.

Frontend

1. La tasa de renovación se muestra con dos decimales, junto con el número de membresías canceladas y la tasa de cancelación.
2. El reporte muestra una fila por mes dentro de un rango de hasta 12 meses para comparar las tasas.
3. Cuando no hay membresías vencidas en el mes, la fila muestra el texto «Sin datos para el periodo», no 0 % ni un error de división por cero.
   Backend
4. Tasa de Renovación, el miembro tiene una nueva vigencia pagada que empieza hasta 30 días después del vencimiento. Cancelada: vencida y no renovada en esos 30 días. Solo se cuentan vencidas con 30 días ya transcurridos.
5. El sistema no permite un rango mayor a 12 meses ni uno con fecha final anterior a la inicial (400).
6. Los valores coinciden con los datos del Módulo 1.
7. MIEMBRO y ENTRENADOR reciben 403 y el mensaje «Acceso denegado».

## Diseño backend e implementación

- **Módulo(s):** `reports`.
- **Endpoint(s)/componente(s):** `GET /api/v1/reports/retention`.
- **Modelos Prisma implicados:** `Membership, Payment`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h38.seed.ts`; utiliza fixtures compartidos del grupo `core + classes + slots + routines + machines` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/reports/reports-math.spec.ts`.

## Archivos fuente de referencia

- `src/reports/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
