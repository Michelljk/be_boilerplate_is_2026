# H37 — Reporte de ingresos totales

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H37.

Frontend

1. Para el rango elegido, el reporte muestra el total de ingresos en USD con dos decimales, desglosado en Membresías y Sesiones adicionales. Sin pagos en el rango, muestra $0.00 en el total y en cada concepto.
   Backend
2. El rango se aplica sobre la fecha del pago.
3. El total suma únicamente pagos en estado PAGADO y excluye los ANULADO y los PENDIENTE.
4. El sistema no permite un rango mayor a 12 meses ni uno con fecha final anterior a la inicial (400).
5. Los valores coinciden con los pagos PAGADO del Módulo 5 (H16, H19 y H21).
6. MIEMBRO y ENTRENADOR reciben 403 y el mensaje «Acceso denegado».

## Diseño backend e implementación

- **Módulo(s):** `reports`.
- **Endpoint(s)/componente(s):** `GET /api/v1/reports/income`.
- **Modelos Prisma implicados:** `Payment, Membership`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h37.seed.ts`; utiliza fixtures compartidos del grupo `core + classes + slots + routines + machines` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/reports/reports-math.spec.ts`.

## Archivos fuente de referencia

- `src/reports/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
