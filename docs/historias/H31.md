# H31 — Aviso de vencimiento de membresía

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H31.

Frontend

1. El aviso aparece en la bandeja (H34) con título «Tu membresía vence pronto» y mensaje «Tu plan <plan> vence el <dd/mm/aaaa>. Renuévalo para no perder el acceso.».
   Backend
2. El sistema genera un aviso 7 días y otro 1 día antes de la fecha de vencimiento de una membresía vigente, con el nombre del plan y la fecha de vencimiento. Aplica a todos los planes, incluidos los de clases.
3. Una tarea programada corre una vez al día a las 6:00 a. m. y los avisos aparecen en la bandeja al terminar la ejecución.
4. El sistema no envía aviso a un miembro cuya membresía ya fue renovada ni más de un aviso por umbral para la misma membresía, aunque la tarea corra dos veces el mismo día.
5. La historia llama a H35 con módulo MEMBRESIAS y dedupeKey VENC- <membershipId>-7 o VENC-<membershipId>-1. No tiene lógica propia de envío.

## Diseño backend e implementación

- **Módulo(s):** `notifications`.
- **Endpoint(s)/componente(s):** `Tarea programada (sin endpoint HTTP)`.
- **Modelos Prisma implicados:** `Membership, MembershipPlan, Notification`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h31.seed.ts`; utiliza fixtures compartidos del grupo `core` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/notifications/domain/notification-templates.spec.ts; src/notifications/services/notification-dispatcher.service.spec.ts`.

## Archivos fuente de referencia

- `src/notifications/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
