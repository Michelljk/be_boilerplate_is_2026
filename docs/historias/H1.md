# H1 — Consulta del estado de membresía

## Historia y criterios

Fuente: _HISTORIAS_USUARIO_GKDS_PROYECTO_2_IS_02_2026.pdf_, historia H1.

Frontend
• El miembro ve en una tarjeta “Mi membresía” el nombre del plan, fecha de inicio, vencimiento, beneficios y etiqueta “Vigente” o “Vencida”.
• Si no existe membresía, se muestra “No tienes una membresía registrada” y no se muestran fechas inventadas.
Backend
• El estado se calcula con fechas y créditos restantes: para POR_CLASES, 0 créditos implica VENCIDA, aunque la fecha de fin no haya llegado.
• El miembro autenticado no puede consultar la membresía de otro miembro; una consulta por identificador ajeno se rechaza.

## Diseño backend e implementación

- **Módulo(s):** `memberships`.
- **Endpoint(s)/componente(s):** `GET /api/v1/memberships/me`.
- **Modelos Prisma implicados:** `User, Membership, MembershipPlan, Payment`. Se declaran en el esquema único `prisma/schema.prisma`; no se mantiene un schema independiente por historia.
- **Datos demo:** seed de historia `prisma/seeds/h1.seed.ts`; utiliza fixtures compartidos del grupo `core` para conservar coherencia entre historias y permitir repetir el seed.
- **Pruebas asociadas:** `src/gkds/membresias/membership-dates.spec.ts; src/memberships/domain/eligibility.spec.ts`.

## Archivos fuente de referencia

- `src/memberships/`
- `prisma/schema.prisma`
- `prisma/migrations/` (historial SQL acumulativo; una migración puede cubrir varias historias).

> El seed prepara cuentas y datos base de demostración; no simula acciones transaccionales sensibles (p. ej. cobrar, cancelar, registrar asistencia) como si un usuario las hubiera ejecutado. Esas operaciones se prueban llamando a la API con la identidad y rol adecuados.
